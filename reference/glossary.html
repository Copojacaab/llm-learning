Glossary

One meaning per word, used the same way in every lesson · Cheat sheet · Evals

Token
The unit a model reads and writes: a word or a piece of a word. Speed is measured in tokens per second.
Sampling
How the model chooses the next token: it gives a probability to every possible token, then one is picked at random following those probabilities. Source. First used in Lesson 2.
Temperature
A number that controls how random the sampling is. Low = likely tokens win more often. 0 = the most likely token always wins. Ollama default: 0.8. Source.
Greedy decoding
Always taking the most likely token. It is what temperature 0 does.
Seed
The starting number of the random generator. Same seed and same prompt give the same text.
Repeatable
Same input gives the same output on every run. It says nothing about the output being correct.
Structured output
An answer forced to follow a JSON schema, with the format field. The limit is applied while tokens are picked, so the shape is always right. The values can still be wrong. Source. First used in Lesson 3.
JSON schema
A description of the shape of a JSON object: field names, types, which fields are required. You get it from a Pydantic class with model_json_schema().
Validation
Checking that a text has the fields and types of the schema (model_validate_json). Valid says nothing about the values being correct.
Streaming
Receiving the answer in chunks while it is generated, instead of all at the end. The generation is the same; only the delivery changes. First used in Lesson 1.
Chunk
One piece of a streamed answer. The last chunk has done = True and carries the statistics.
Load / keep-alive
Loading copies the model into GPU memory before the first answer. Keep-alive is how long it stays there after a call (default 5 minutes).
Eval
A repeatable test that measures the quality of a model's output on fixed inputs: cases + ground truth + score. Evals reference. (Not the same thing as the field eval_count, where "eval" only means "tokens the model computed".)
Ground truth
The correct output for an eval case, checked by a human. The model's output is compared against it. First used in Lesson 4.
Eval case
One fixed input of an eval, with its ground truth. Example: one invoice file plus its 6 true field values.
Score
The number an eval produces, e.g. correct fields out of total fields (18/24). Compare scores only on the same set of cases.
Overfitting
Tuning a system (prompt, seed, schema) until it works on the few examples you tried, so it looks better than it is on new inputs. An eval on many cases shows it.
