Evals

Quick reference · Glossary · Cheat sheet · First used in Lesson 4

The three parts

Casesfixed inputs (documents, questions)
Ground truthcorrect output per case, checked by a human
Scorefunction output vs truth → a number (e.g. correct fields / total fields)

Field-level eval for extraction

expected = json.loads(Path("samples/expected.json").read_text())
right = {f: 0 for f in Invoice.model_fields}
for name, want in expected.items():
    inv = extract((SAMPLES / name).read_text(), temperature=0)
    got = inv.model_dump() if inv else {}
    for f in right:
        if same(got.get(f), want[f]): right[f] += 1
        else: print(name, f, got.get(f), want[f])   # always look at failures
print(f"score {sum(right.values())}/{len(expected) * len(right)}")

same(): strings with .strip().casefold(), floats with round(x, 2), else ==.

Rules

Temperature 0repeatable output → one run per case is enough
Several casesa fix on one case can break another; tuning on one case = overfitting
Human truthnever let the model write the expected values
One change at a timescore after each change, keep a table
Print failuresthe score says how much, the failures say what to fix

Levels (Hamel Husain)

1 · unit tests: assertions written by hand (this page) · 2 · human and model review of traces, for free text · 3 · A/B tests with real users. Source: Your AI Product Needs Evals.
