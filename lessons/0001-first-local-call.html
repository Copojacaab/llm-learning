Your first local LLM call

Lesson 1 · 30 minutes · Mission · Cheat sheet

Today's win: a Python script of yours sends a question to a model running on your own GPU, and prints the answer and the speed in tokens per second. This is the base of the morning-briefing agent: every agent step is a call like this one.

The idea in 4 lines

Ollama is a program that runs models on your computer. It starts a small web server on localhost:11434. Your Python code talks to it with the ollama library, which sends HTTP requests to the /api/chat endpoint. No cloud, no cost, and your documents stay on your machine.

Step 0 · Give WSL more memory (5 min)

WSL sees only 7.6 GB of RAM now. The model itself will live in your 8 GB of GPU memory, but more RAM avoids trouble later. In Windows, create C:\Users\<you>\.wslconfig:

[wsl2]
memory=12GB

Use about 70% of your real Windows RAM (12GB is right for a 16 GB laptop; change it if yours differs). Then in PowerShell run wsl --shutdown and open WSL again. Source: Microsoft Learn, .wslconfig.

Step 1 · Install Ollama and a model (10 min)

curl -fsSL https://ollama.com/install.sh | sh
ollama -v
ollama pull llama3.2:3b
ollama run llama3.2:3b

The last command opens a chat. Ask something, then type /bye. Install steps: Ollama Linux docs. llama3.2:3b is small (about 2 GB) so it downloads fast; it is a tool-capable model. We will test bigger ones later.

In a second terminal, run nvidia-smi while the chat answers. You should see memory used on the GPU.

Step 2 · Call it from Python (10 min)

cd ~/llm-learning
python3 -m venv .venv
source .venv/bin/activate
pip install ollama

Now write this yourself (do not paste; type it, it is short). Create hello_llm.py:

from ollama import chat

response = chat(
    model="llama3.2:3b",
    messages=[{"role": "user", "content": "In one sentence: what is a Python venv?"}],
)

print(response.message.content)

seconds = response.eval_duration / 1e9
print(f"{response.eval_count} tokens, {response.eval_count / seconds:.1f} tokens/s")

Run it: python hello_llm.py. Code pattern from the official README; the eval_count and eval_duration fields are described in the API docs (duration is in nanoseconds, so we divide by 1e9).

Experiments (5 min, do at least two)

  • Run the script twice. Is the second run faster? Look at response.load_duration.
  • Add stream=True and print chunks as they come (see the cheat sheet).
  • Ask the same question 3 times. Do you get the same answer? We will use this in the next lesson about temperature.
