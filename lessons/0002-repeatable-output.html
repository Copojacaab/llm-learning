In lesson 1 you added stream=True and had to comment out the speed lines. The reason: with streaming, chat() does not return one response. It returns a sequence of chunks. The statistics (eval_count, eval_duration, load_duration) are in the last chunk, the one where chunk.done is True.

Task: in hello_llm.py, print tokens/s again, after the streamed text. Hint: in Python the loop variable still exists after a for loop, and it holds the last item.

Solution

    print(chunk.message.content, end="", flush=True)

seconds = chunk.eval_duration / 1e9
print(f"\n{chunk.eval_count} tokens, {chunk.eval_count / seconds:.1f} tokens/s")

The idea

A model does not write a sentence. It writes one token, then the next, then the next. At each step it gives a probability to every possible token, and one is picked at random, following those probabilities. This is called sampling (Hugging Face: How to generate text). That is why you got answers that were "more or less" the same in lesson 1: similar, but not equal.

Two options control the dice:

temperatureHow random the pick is. Ollama's default is 0.8. Higher = more surprising tokens. At 0 the most likely token always wins, so there is no randomness left. (Ollama: parameters)
seedFixes the random numbers. "Setting this to a specific number will make the model generate the same text for the same prompt." (same page)

You pass them in the options field of the request (API docs):

chat(model=..., messages=..., options={"temperature": 0})

Step 2 · Write repeat.py (12 min)

In exercises/, write it yourself from this spec:

  • A function count_answers(prompt, n=10, **options).
  • It calls chat() n times with the same prompt, no streaming, and passes options=options.
  • It cleans each answer with .strip() and counts equal answers. collections.Counter is made for this.
  • It returns the counter. The main part prints each answer with its count, most common first, and the number of different answers.

Try for 10 minutes before you open the solution. The struggle is the lesson.

Solution (open only after trying) 
from collections import Counter
from ollama import chat

MODEL = "llama3.2:3b"


def count_answers(prompt, n=10, **options):
    counts = Counter()
    for _ in range(n):
        response = chat(
            model=MODEL,
            messages=[{"role": "user", "content": prompt}],
            options=options,
        )
        counts[response.message.content.strip()] += 1
    return counts


prompt = "Invent a name for a cat. Answer with the name only."
counts = count_answers(prompt)
for answer, times in counts.most_common():
    print(times, answer)
print(len(counts), "different answers")

What this means for your agents

JobSettingWhy
Extract fields from an invoice, classify, decidetemperature: 0Same document must give the same fields, or you cannot measure accuracy or reproduce a bug.
Write the morning briefing textdefaultText for a human; small variations do no harm.
Run an evaltemperature: 0, or a fixed seedIf the score changes, the cause is your change, not the dice.

One warning. Repeatable does not mean correct. At temperature 0 a model that reads a total wrong will read it wrong every time, with full confidence. Repeatability only makes the error measurable. Measuring it is the job of evals, two lessons from now.
